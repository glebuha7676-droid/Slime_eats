# Ресурсное заражение и компактная баночка v19

Жидкость на породе терялась среди блоков. Пользователь попросил соединить её с контрастными лозами и заметными цветками и уточнил финальную схему:

- +1: один средний цветок, пара коротких лоз и немного жидкости.
- +3: один средний цветок, 2–3 маленьких, больше жидкости между ними. В текущем рисунке два маленьких цветка.
- +5: один крупный цветок прямо по центру, дополнительные по бокам, выраженный разлив жидкости.

Небольшой тёмно-сливовый контур, светлые края лепестков, фиолетовые лозы, жёлто-лаймовая жидкость со сливочными бликами. Стадии должны читаться на любых материалах при размере клетки 48–64 px. Не превращать их в плотную одинаковую цветочную массу или отдельные жидкостные значки с толстой белой каймой. Прозрачные промежутки сохраняют видимость исходной породы.

Баночка — компактная в пропорциях первоначальной, без длинного корпуса, массивных зажимов и чрезмерной ширины. Короткая сливовая крышка с простым лепестковым знаком, голубоватое стекло, контрастная жёлто-лаймовая струя на тёмном внутреннем фоне, небольшая светлая эмблема цветка без надписей. Использован компактный вариант v18.

Ассеты: `assets/ui/mutation-flowers-v19/infection-1.webp`, `infection-3.webp`, `infection-5.webp` (384×384 RGBA), `jar.webp` (256×256 RGBA). Совместимые пути прежней эссенции и баночки перенаправлены, обновлены статичные картинки интерфейса и гардероба. Награды +1/+3/+5 и их механика сохранены.

Генерация встроенным image_gen; мастера, окончательные промпты, источник баночки и метаданные — `output/concepts/mutagen-flowers-v19/`. `preview.html` показывает три стадии на всех 12 материалах четырёх миров, клетки 64 px; рядом обычные игровые кадры `natural-world-*` и проверочные кадры с размещёнными для сравнения стадиями.

`tools/preview_mutagen_flowers_v19.cjs` проверяет локальную игру в 440/320 px: изображения, совместимые пути, новую баночку HUD, возрастающую площадь стадий и прежние награды. `tools/test_caves_file_v15.cjs` дополнительно проверил обычные анимированные локальные запуски четырёх миров при чистой и заражённой стадии, без ошибок. Проверка продвижения кадров ожидает реальные кадры с ограничением времени, а не предполагает фиксированную частоту на загруженной машине.
