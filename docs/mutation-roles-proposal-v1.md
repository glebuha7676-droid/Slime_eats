# Роли мутаций под сохранение Силы — проект следующей переработки

Это предложение, не список уже реализованных изменений.
Сейчас внедрена только новая прогрессия огня.

Общая цель: каждый персонаж по-своему уменьшает опасные контакты,
но сохраняет управление, сбор ресурсов и риск. Три стадии должны
усиливать один способ прохождения, а не просто добавлять число снарядов.
Пассивное развитие относится к достигнутой стадии мутации; старую
ультимативную способность можно выбрать без отката пассивного развития.

| Мутация | Способ прохождения | Последовательность пассивного развития I → II → III | Что переработать |
|---|---|---|---|
| Огонь | Постепенно выжигает пласт | Касание → один крест передачи → полное догорание | Уже внедрено. Урон медленный, зато конечный охват читаем |
| Мороз | Подготавливает лёгкий проход | Превращает встреченный блок в хрупкий → подготавливает следующий ниже → короткая полоса подготовленных блоков | Убрать случайное разбрасывание осколков по дальней шахте. Заморозка колючки временно подавляет её, но не удаляет всю опасность |
| Электро | Быстро расшивает небольшие группы | Короткий разряд вперёд → ограниченная цепь соседей → более сильный удар по прочным целям цепи | Меньше ударов вверх/в стороны без пользы. Не соединять далёкие блоки через пустоту |
| Космос | Пробивает скоростью | Орбитальная планета подбивает ближайшую преграду → после свободного падения помогает пробить один ряд → короткий мощный прорыв после разгона | Ограничить пассивное пробивание бюджетом, затем восстановление разгоном. Колючки вне активного прорыва остаются опасными |
| Техно | Заранее расстреливает выбранный проход | Один дрон стреляет вниз → концентрируется на прочной преграде → заряженный выстрел по узкой колонне | Убрать мгновенное уничтожение любого HP как универсальное решение. Приоритет ближайшего будущего контакта; конечная скорострельность |
| Псионика | Разбирает и использует преграды | Вырывает ближайший мешающий блок → бросает в следующий → тяжёлый бросок пробивает несколько контактов или одну колючку | Выбор полезных блоков впереди вместо произвольного мусора сбоку. Ограничить массу/число целей |
| Фантом | Проходит препятствие насквозь | Краткое прохождение через один блок после подготовки → метка на пройденном блоке → короткая цепь прохождения с последующим взрывом | Конечный запас фазы и явное восстановление. Не постоянная неуязвимость. Сквозь жилу можно проскочить, не собрав её: выбор пути сохраняется |
| Споры | Готовит взрыв впереди | Семя на ближайшем будущем препятствии → расползание по небольшой связной группе → управляемый каскад внутри этой группы | Убрать случайные грибочки позади слайма. Посадка и взрыв должны успевать подготовить путь; ограничить задержку и группу |
| Глитч | Обезвреживает и переписывает локальный участок | Помечает одну опасную/прочную клетку → связывает несколько соседних → изменяет небольшой участок перед слаймом | Самая серьёзная переработка: понятные, предсказуемые преобразования вместо случайных подарков/глобального удаления. Сохранять возможность выбирать сбой ультой |

Порядок: огонь → мороз → техно → фантом → космос → псионика → споры →
электро → глитч. Сначала довести несколько различимых стилей, затем
переносить общий подход на остальные. Не включать все новые системы сразу.

## Ограничения баланса

- Ни одной универсальной автоматической защиты от всех колючек.
- Щиты и фаза имеют явный конечный запас/период, не сочетаются с бесконечным
  восстановлением. Не вводить отдельные управляемые кнопки для каждой пассивки.
- Рывки не должны складываться с ультами в почти полный автоматический
  пролёт500m; оценивать безопасную дистанцию и долю забега без участия.
- Для всех сохранить один ресурс «Сила», общую понятную зарядку ульты,
  один финальный удар от сохранённого запаса. Не вводить девять скрытых
  экономик для детей.
- Прокачка должна уменьшать вынужденные контакты и открывать новое
  поведение. Нельзя просто сделать старые формы неприятными ради III.
- Проверять на одинаковых картах: потерянная Сила, попадания на колючки,
  собранные сгустки/валюта, частота ульты, время и ручное управление.
  Разброс между мутациями допустим, постоянный победитель по всем метрикам — нет.

Перед переносом каждой строки в код нужно конкретизировать дальность,
частоту, бюджеты и слабую сторону на существующих500m. Формулировки
выше задают роли; это ещё не проверенный числовой баланс.
